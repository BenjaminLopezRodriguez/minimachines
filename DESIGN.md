# Mini Machines design system

The visual foundations retain Mini Machines’ cobalt identity and supplied logo, with IBM Plex Sans for approachable, compact interface typography and IBM Plex Mono for code. Light and dark surfaces are neutral and softly tinted. Public storytelling is conversational and project-led, inspired by Muse’s emphasis on useful work and clear human decisions.

- `src/styles/globals.css` owns the semantic colors for both themes. Public pages, Git, Bots and portal dialogs inherit these tokens. Avoid component-specific light or dark palettes.
- `--background` is the canvas, `--surface` the sidebar, and `--card` an elevated content surface. `--foreground` and `--muted-foreground` are text colors; `--signal` marks navigation and links. Status and diff colors use the success, warning and destructive tokens with corresponding soft surfaces.
- Use 12–16px corners for panels and fields, full pills for main actions, and 44px targets for primary controls. Keep code in IBM Plex Mono.
- Appearance offers Light, Dark and System. The system preference is the default; explicit choices persist in local storage. A head script applies the preference before paint. Do not force a theme inside a product shell.
- `BrandMark` renders the supplied SVG geometry using `--brand`. The same artwork is available as `public/logo.svg`, the favicon and Apple home-screen icon.
- Keep focus rings visible, body text at 4.5:1 contrast, semantic diff labels alongside color, and responsive navigation usable at 390px. Honor reduced motion.

Use compact container spacing: 12–16px in panels, 16–24px in content areas, and 24–32px around forms or empty states. Avoid accumulating large insets across nested containers. Preserve 44px phone touch targets.

Phone workflows use progressive disclosure: the mobile hamburger opens navigation and chat history; tap a file for a focused diff with Back; reveal repository controls, filters and forms when needed. Keep the browser’s bottom area free of app navigation. Desktop shows the chat sidebar at 1100px and wider; narrower layouts use a drawer.

`src/styles/materials.css` refines the shared components with restrained glass materials. Controls use a fine specular highlight and short relief shadow; menus and dialogs use a highly opaque translucent material. Broad content panels use neutral tint instead of repeated outlines or blur. Keep data and code surfaces quiet. Compact desktop controls expand to 44px targets on touch devices. Preserve visible focus, reduced-motion, reduced-transparency and forced-colors alternatives.

The default dashboard is a messenger centered on Bot conversations. Follow the user's October 25, 2026 Cursor brief for the application chrome: one floating top row with a fully transparent, blurred backdrop. The mobile hamburger, Bot / Whiteboard text capsule, and new-chat action sit inline. Individual controls use white circles or pills with restrained backdrop shadows, adapting to the active theme. The toolbar floats above content but below drawers and dialogs; content scrolls beneath it without hiding initial content or blocking canvas input. Preserve a solid fallback for reduced transparency.

On mobile, Bot mode has one hamburger that opens chats, bot settings, feedback, page destinations and sign-out. Whiteboard uses the existing page menu. Hide the mobile appearance toggle. On desktop, keep the branded page switcher and simplify the sidebar to New chat, history, and secondary settings and feedback. Machines, Git, team, credentials and docs remain discoverable through navigation. No bottom navigation.

Chat opens onto a quiet conversation canvas with its composer at the bottom. The latest Cursor direction supersedes the earlier request for a persistent suggestions banner and welcome prompt list: remove both from the main conversation, along with the extra "Your bots" toolbar, duplicated chat header and generic accuracy disclaimer. Keep feedback and bot customization in secondary settings or the drawer. Use larger readable messages; assistant replies have no decorative bubble or repeated name label. The rounded composer grows with the draft. Agent selection is the essential connection choice; default the name, tone, workspace and verified email when possible. Preserve the draft during sign-in, ask at most one genuinely blocking question, and explain compute cost only at the action that starts compute. Apply the same UX direction to the standalone /bots route.

Whiteboard opens immediately on a browser-local Excalidraw canvas, with the drawing palette at the bottom. A right-edge tick rail scrubs up to 120 cached edits; history previews are read-only, onion skins show prior changed elements, and restoration appends a new edit. Local canvas drafts and history are scoped to the signed-in user in IndexedDB and are not automatically shared with project rooms.

Cursor is currently implementing the shell chrome. Coordinate through the current files and this brief: avoid bulk file syncs or replacing messenger, chat surface, workspace, or shell styles with older versions. Preserve concurrent edits and reconcile only the specific integration that is needed.

Mobile task flows use one clear primary action per step and native form behavior. Agent connection presents Workspace → Sign in → Ready, checks the account when returning from sign-in, and hides installation and account management under disclosure. A new bot’s Continue action becomes available only after its connection is confirmed; existing bot preferences remain editable while offline. Early access asks only for email; testing preferences and interview consent stay optional after verification, with workspace access before those fields. Baton replies show the question before opening the keyboard, preserve the answer across send failures, and use a reachable send action with a pending state. Distinguish “reply saved” from observed agent activity; disclose command logs under Activity details. Keep these task-flow styles scoped separately from Cursor’s application chrome.
